## 两处确定的处理问题及修复

1. 旧冒烟在检测到任意 NaN/Inf 后立即退出，没有让 GradScaler 跳过该次 SGD 并降低 scale；将可能的初始缩放校准也当作机制失败。现在最多允许 --max-amp-skips 次原生跳步，--steps 统计真正成功的 optimizer 更新次数；默认最多 8 次，总尝试次数也有上界。梯度缺失、非有限前向、FP32 非有限、跨 rank 有限性不一致仍立即报错。超过恢复预算不判通过。
2. 正式 processor 原来每个 batch 都更新 GPD 原型，包括 GradScaler 跳过 SGD 的 batch。现在仅 SGD 真正执行时更新原型，避免原型状态与参数更新不同步；该修正同时用于 baseline 和 QG。

新增 solver/amp_step.py 供正式 processor 与 preflight 共用。调用顺序为 backward→unscale→检查：有限梯度沿用 max_norm=1 的原裁剪→原生 scaler.step/update；非有限时不裁剪，也不把 NaN 改为 0，而是由原生 scaler.step 跳过更新、scaler.update 降低尺度。参数和 SGD momentum 不因跳步而更新；前向 BN running statistics 仍按通常训练行为更新，不声称整份 state_dict 完全不变。

DDP 中先核对所有 rank 对梯度有限性的判断一致，再走相同步骤，避免不同 rank 分别更新/跳过。正式训练记录每次跳步，连续 8 次溢出硬停止。预训练、学习率、四项损失、24 个调制参数、掩码和模块公式都未改；不将初始 scale 人为改小。

官方依据是 PyTorch v1.12.1 GradScaler 源码：
https://github.com/pytorch/pytorch/blob/v1.12.1/torch/cuda/amp/grad_scaler.py
其中明确说明初始若干迭代可能出现 inf/NaN，step 会跳过 SGD，update 按 backoff_factor 降低 scale。恢复不等于持续异常可以忽略。
