# 单卡第二步梯度异常：2026-11-04

## 已知事实

服务器第一步 loss=40.16996，CE=6.21663，WRT=33.91121，ProCA=0.43484，GPD=0.03777；裁剪后 QG 梯度范数约 0.03019，24 张图，无空掩码。零初始化前向统计均为 0，符合预期。第二步在 backward 和 unscale 后报告 blocks.0.attn.qg_alpha_raw 的 missing/nonfinite 合并错误。原日志未提供第二步损失、scale、梯度是否 None 或 NaN/Inf，因此不能确认根因。

torchvision interpolation 的弃用警告不是本次 AssertionError。

## 本轮处理

只修改 tools/preflight_qg.py，新增 tests/test_preflight_qg.py；不修改正式 train.py、processor、模型、优化器、四项损失或掩码。没有放宽断言，也没有把不正常梯度替换为零。

- 区分梯度 None 与 NaN/Inf。
- 失败也保存 JSON，包括第二步四项损失、scale、输出 dtype/幅度、24 个调制梯度的有限性、全部参数中非有限梯度的位置。
- --diagnose-loss-gradients：单进程同一计算图，分别探测按正式权重组合的各损失和总损失，对比未缩放/按当前 scale 缩放的 QG 梯度。不累积 .grad，不更新参数；DDP 禁用此探测。
- --precision fp32：禁用 autocast 和 GradScaler，作为对照。FP32 通过不会标成 AMP 通过。
- --init-scale 保留默认 65536，可用于后续隔离；当前不擅自降低默认值。
- --detect-anomaly 为需要进一步定位算子时的可选入口。

CPU 回归测试复现：FP32 参数、有限前向，在经过 FP16 中间值的反传中，未缩放梯度有限，乘 65536 后梯度 Inf。它证明这一失败模式可能存在，不证明服务器本次必然属于该原因。

## 判读与下一步

先暂停正式训练和多卡升级，不重新生成掩码。运行增强 AMP 探测及相同 seed/batch 的 FP32 对照，将两份 JSON 和控制台日志送回复核。

- 同一 AMP 图未缩放梯度有限、缩放后异常：优先检查 loss scaling 溢出。GradScaler 在正式训练中能跳步/降尺度，旧冒烟遇到一次就退出，不能仅凭此认定模型机制失效；仍需验证恢复情况。
- AMP 图未缩放也异常，但 FP32 对照通过：优先检查混合精度中间计算或梯度路径。
- FP32 也异常：进一步检查数值、输入、权重和具体损失路径。
- 梯度 None：检查图连接、参数是否使用及版本差异，不按数值溢出处理。

不将这些分支仅凭现有日志任选其一。FP32 是独立对照，第二步状态并非与 AMP 完全相同；更直接的尺度证据来自同一 AMP 图的未缩放/缩放探测。

没有服务器 GPU 和完整输入，当前没有宣称真实异常已经修复。失败报告用于下一步有依据地修复。
