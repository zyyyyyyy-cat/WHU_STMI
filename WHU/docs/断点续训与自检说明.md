# 断点续训与代码自检

## 实现范围

支持单卡和 torchrun DDP，在最近一个完整 epoch 的训练及该轮验证结束后恢复。
每轮都原子更新 OUTPUT_DIR/checkpoint_last.pth，不受 CHECKPOINT_PERIOD=120 影响。
中断发生在 epoch 中途时，重启后重新执行该 epoch；不恢复批次游标或后台预取队列。
第一个 epoch 尚未保存成功就中断时，没有可恢复的完整断点。

原有 transformer_120.pth 等模型权重仍按 CHECKPOINT_PERIOD 保存，供 test.py 使用。
完整断点包含优化器等状态，体积明显大于仅模型权重；保存期间还需要临时文件空间。
写入使用同目录临时文件、flush/fsync、os.replace；写入失败保留上次完整断点。
强制杀进程可能留下 .tmp 文件，但恢复入口不会使用它。

这次未修改共享 ViT-B、QG 调制公式、24 个可学习标量、图像/掩码联合变换、
CE/WRT/ProCA/GPD、PKM 抽样策略、原型更新公式和评估协议。
仍为 L=CE+WRT+0.01*ProCA+GPD；单卡/DDP 原有训练与验证分工保留。

## 保存和恢复内容

|状态|处理|
|---|---|
|模型参数与缓冲区|严格加载全部参数，包括 classifier、QG 标量和模型元数据|
|各卡 BN 等 buffer|分别保存；DDP 包装完成后恢复每卡自己的 buffer|
|主优化器|保存参数分组、当前 LR、SGD 动量等全部 state_dict；校验参数名称和分组顺序|
|center criterion 与其优化器|同时保存和恢复；即使本实验不使用该损失也不遗漏其状态|
|学习率调度器|保存状态；下一轮按原代码 scheduler.step(epoch) 继续，不重启 warmup|
|AMP|每卡保存 scaler 的 scale 和增长计数；恢复后不重新从 65536 校准|
|GPD 原型库|保存完整 prototypes，恢复后继续原有更新|
|随机数|分别保存每卡 Python、NumPy、torch CPU 和本卡 CUDA RNG|
|采样器|恢复 length 和已有的 _seed；PKM 下一轮仍使用原算法和已恢复 RNG|
|训练计数|完成 epoch、累计成功更新数、AMP 跳步数、连续溢出次数|
|实验标识|保存训练配置、按顺序的图像/身份/相机/模态记录摘要、掩码 manifest SHA256、torch/CUDA 版本|

完整断点在验证结束后保存，因为验证 DataLoader 创建迭代器也会消耗 RNG。
所有 rank 都参加状态收集，包括四卡验证时没有分到模态的第四卡。
仅 rank 0 写文件；可捕获的单卡读取错误、rank 0 写入错误会传播给所有 rank。
进程硬退出和节点失联仍由 torchrun/NCCL 的故障处理机制负责。

## 恢复约束

- 单卡续单卡，四卡续四卡；恢复时进程数、DIST_TRAIN、全局 batch、worker 数必须保持。
- 保持总轮数、学习率、训练/验证配置、身份映射、模态顺序和 torch/CUDA 版本。
  MAX_EPOCHS 是原训练的总目标，例如一直为 120，不能改成“剩余轮数”。
- 允许修改输出路径、日志/权重保存频率、设备编号、预训练路径及数据根路径。
  图片记录与掩码 manifest 内容必须一致。恢复时直接加载完整模型，不再读取 ImageNet 预训练。
- 图片和掩码本身应保持冻结。恢复入口只校验记录与 manifest 摘要，不重新逐像素审计所有数据。
- 当前 DataLoader 为非 persistent workers、默认 RNG；本次不支持后台 persistent worker 状态恢复。
- 只加载自己生成的完整断点。旧版仅模型权重缺少优化器/原型等状态，无法补算成完整断点。
- 已启动的旧进程不会因为磁盘上同步了新代码就获得此功能；新功能必须从新版启动的进程开始使用。

空 SOLVER.RESUME 表示新实验。若 OUTPUT_DIR 已有 checkpoint_last.pth，会拒绝覆盖并提示恢复或换目录。
没有“自动挑选最新文件”的隐式行为，避免误用其他实验。恢复路径必须明确指定。
若断点已完成 120 轮，再次恢复仅提示已完成，不额外训练。

## 四卡首次训练

服务器项目目录直接包含 train.py、configs、utils 等，不要再添加一层 WHU。
掩码已离线生成、全量审计完成，无需启动 wsam 或加载 SAM。

```bash
conda activate clipreid
cd /project/code/WHU_base/WHU_STMI
mkdir -p logs
set -o pipefail

CUDA_VISIBLE_DEVICES=0,1,2,3 torchrun --standalone --nproc_per_node=4 \
  train.py --config_file configs/UAD.yml \
  MODEL.DIST_TRAIN True \
  MODEL.PRETRAIN_PATH /project/code/data/jx_vit_base_p16_224-80ecf9dd.pth \
  DATASETS.MASK_ROOT /project/code/data/WHU-MARS_masks_R08_v1 \
  DATASETS.MASK_MANIFEST /project/code/data/WHU-MARS_masks_R08_v1/manifest.json \
  SOLVER.IMS_PER_BATCH 256 SOLVER.BASE_LR 0.008 \
  SOLVER.MAX_EPOCHS 120 SOLVER.SEED 1234 \
  TEST.IMS_PER_BATCH 32 DATALOADER.NUM_WORKERS 2 \
  OUTPUT_DIR ./logs/UAD_QG_SFM_R08_4GPU_seed1234 \
  2>&1 | tee -a logs/UAD_QG_SFM_R08_4GPU_seed1234.console.log
```

256 是四卡合计的三模态样本组，每卡 64 组、192 张图；未在本地验证此配置的 3090 显存。
如第一轮前出现 OOM，可将新实验的 batch 改为 128，随后恢复始终保持 128；对照 baseline 也应匹配。
已有完整断点后不能通过修改 batch 将其当作等价续训。

## 四卡中断后继续

确认旧训练进程已退出，再执行。除增加 SOLVER.RESUME 外，保持首次训练的实际配置。
如果首次使用了 128，下方 256 必须同步改为 128。

```bash
conda activate clipreid
cd /project/code/WHU_base/WHU_STMI
mkdir -p logs
set -o pipefail

CUDA_VISIBLE_DEVICES=0,1,2,3 torchrun --standalone --nproc_per_node=4 \
  train.py --config_file configs/UAD.yml \
  MODEL.DIST_TRAIN True \
  MODEL.PRETRAIN_PATH /project/code/data/jx_vit_base_p16_224-80ecf9dd.pth \
  DATASETS.MASK_ROOT /project/code/data/WHU-MARS_masks_R08_v1 \
  DATASETS.MASK_MANIFEST /project/code/data/WHU-MARS_masks_R08_v1/manifest.json \
  SOLVER.IMS_PER_BATCH 256 SOLVER.BASE_LR 0.008 \
  SOLVER.MAX_EPOCHS 120 SOLVER.SEED 1234 \
  TEST.IMS_PER_BATCH 32 DATALOADER.NUM_WORKERS 2 \
  SOLVER.RESUME /project/code/WHU_base/WHU_STMI/logs/UAD_QG_SFM_R08_4GPU_seed1234/checkpoint_last.pth \
  OUTPUT_DIR ./logs/UAD_QG_SFM_R08_4GPU_seed1234 \
  2>&1 | tee -a logs/UAD_QG_SFM_R08_4GPU_seed1234.console.log
```

恢复日志应出现 `Resumed full training state ... completed epoch=N; next epoch=N+1; AMP scale=...`。
每轮保存成功应出现 `Full checkpoint saved: epoch=...`。

单卡同理：沿用首次单卡命令、MODEL.DIST_TRAIN False，追加同一实验的 SOLVER.RESUME 路径。
两卡、四卡均使用原 torchrun 入口；不要把预检报告 JSON 当成训练断点。

## 自检方法和边界

本次结果：32 项单元测试全部通过（36.375 秒）；两进程及四进程 Gloo 断点恢复测试通过；
原有两进程 AMP 溢出/恢复测试通过；原始 UAD 对照验证通过。
日志和环境信息见 verification/resume_selfcheck。

自动检查涵盖模型公式、梯度、零初始化等价、图像掩码联合变换、数据读取、优化器分组、
AMP 跳步保护、原型更新、权重兼容、离线掩码工具及恢复状态。
还与保留的原始 UAD 源码对比初始化、12 层注意力/模块输出、CLS/BNNeck/classifier 和各损失。

恢复测试使用真实 PKM sampler、BN、dropout、随机数据增强、SGD、调度器、CPU GradScaler 和原型库。
单卡 0/2 worker 下比较连续训练与重建恢复后的下一轮结果，要求完全相等。
两/四进程 CPU/Gloo 测试精确检查每卡 BN 恢复，并按 rtol=1e-6、atol=1e-7 比较后续浮点结果。
重新构建 DDP 后 reducer 桶布局和归约顺序可能变化，不承诺逐位相同。

本地没有服务器 WHU-MARS 数据、预训练文件或 CUDA/NCCL 运行条件，不能声称已完成真实四卡恢复验证。
服务器先前单卡 20 次成功 AMP 更新只验证了旧阶段训练流程，不等同于本次新增断点逻辑的 GPU 测试。
当前 cuDNN 配置沿用原代码，GPU 训练也不承诺逐位复现；完整状态恢复不代表检索指标一定提升。
